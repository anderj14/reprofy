# Three-minute Reprofy demo

## Before recording

From the repository root, prepare the same clean pagination case used by the README. This creates no model calls and refuses to overwrite an existing directory:

```bash
python scripts/prepare_demo.py --project /tmp/reprofy-video-demo
```

Confirm `.env` contains working Meta credentials without opening the file during recording. Close other terminals and hide notifications. Keep the `ARTIFACTS` directory visible when the CLI prints it.

## Recording outline and narration

### 0:00–0:25 — The problem

**Show:** Repository title and the seeded `list_products` pagination branch.

**Say:** “Small teams often get a bug report without useful reproduction steps. Reprofy turns the report into a reviewed regression test and a proposed source diff. The code stays untouched until a developer approves it.”

### 0:25–0:45 — Start from a clean report

**Show:** Run `list` against the disposable project.

```bash
python -m reprofy list --project /tmp/reprofy-video-demo
```

**Say:** “This fixture has the same seeded bug every time. The report already includes the expected behavior, which gives the agent a requirement to check against.”

### 0:45–1:35 — Generate and inspect

**Show:** Run `fix`, then `show`.

```bash
python -m reprofy fix BUG-001 --project /tmp/reprofy-video-demo --env-file .env
python -m reprofy show BUG-001 --project /tmp/reprofy-video-demo
```

**Say:** “Muse classifies the issue, generates a regression test, and pytest records whether the test reached project code and where it failed. The configured repro model checks that the failure matches the report. Reprofy then proposes a source patch and verifies it against the new test and the full suite in a temporary copy.”

Open `ARTIFACTS/reproduction-attempts/`, `repro-review.json`, `repro-failure.txt`, and `proposal.patch`. Point out that this run is still only a proposal.

### 1:35–2:20 — Human approval

**Show:** Preview with `--check`; then run apply and type `APPLY` after the diff is visible.

```bash
python -m reprofy apply BUG-001 --project /tmp/reprofy-video-demo --check
python -m reprofy apply BUG-001 --project /tmp/reprofy-video-demo
```

**Say:** “The check revalidates the proposal without writing. Apply asks me to review the exact source and test changes. The project changes only after I type the explicit approval.”

### 2:20–2:40 — Verify the result

**Show:** Run `show` and the example test suite.

```bash
python -m reprofy show BUG-001 --project /tmp/reprofy-video-demo
python -m pytest /tmp/reprofy-video-demo/tests -q
```

**Say:** “The bug record now says applied, and the new regression test protects against the duplicate item returning.”

### 2:40–3:00 — Honest evaluation and scope

**Show:** The evaluation table from README.

**Say:** “In one initial three-case run, Meta verified three proposals. The Baseten Muse Spark Open endpoint classified the reports but produced malformed test code across its retries, so Reprofy rejected the tests and proposed no patches. These small results are not a general model ranking. Reprofy currently supports Python and pytest; the widget, watch mode, duplicate detection, and local model option are not implemented.”

## Recording checks

- Do not show `.env` or API keys.
- Do not type `APPLY` until the exact diff is visible and reviewed.
- Leave the original repository untouched; the demo lives under `/tmp`.
- Do not edit the generated test or source by hand during the recording.
- If Muse returns an invalid reproduction or proposal, show that result honestly and use the stored successful run only if it was generated by Reprofy from the same clean fixture.
